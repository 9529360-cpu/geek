# 群发 UI、保存消息与标签修复契约（2026-08-28）

> 适用于 Issue #165 / Draft PR #166。本文承接附件修复契约，处理编辑器 UI、常用消息、群组集合、受众模式和失败导出；不改变版本或发布边界。

## 产品与数据要求

- `BR-UI-001`：发送按钮摘要必须反映当前受众模式；不能把标签受众、全量受众或排除模式显示成“请选择发送对象”。
- `BR-UI-002`：`all / all-contacts / all-groups` 必须从 Job 创建时的完整聊天快照解析，不得受搜索框或旧勾选残留影响。
- `BR-UI-003`：`exclude-contacts / exclude-groups` 的基础受众是完整聊天快照，再应用账号级排除集合；不得沿用上一个模式的勾选结果。
- `BR-SAVE-001`：常用消息和群组集合必须按当前账号持久化；切换账号后只读取该账号数据。
- `BR-SAVE-002`：保存、覆盖、删除必须先确认持久化成功再更新 UI 和提示成功；失败时保留原数据并给出明确错误。
- `BR-SAVE-003`：保存/删除操作执行期间禁用对应按钮，防止快速重复点击造成并发覆盖。
- `BR-SAVE-004`：持久化记录必须经过容错规范化；畸形 JSON、非数组、空名称、空正文和重复 chatId 不得让编辑器崩溃。
- `BR-TAG-001`：群组集合只保存当前选择中的群组 chatId，同名保存原位覆盖；应用集合整体替换当前选择。
- `BR-TAG-002`：“清除集合筛选”只取消筛选，不清空当前已选聊天；删除标签也不删除真实群组或当前选择。
- `BR-FEEDBACK-001`：不得全局改写 `window.alert` 或吞掉保存/完成反馈。
- `BR-FAIL-001`：新 Job 的失败明细必须包含收件人、chatId 和原因，并能从任务条导出 CSV；不能再读取 legacy `broadcastFailed`。

## 安全与边界

- 数据 API 继续使用现有账号沙箱 allowlist，不新增跨账号共享存储。
- UI 文本和持久化名称进入 DOM/CSV 前必须转义；不得把聊天正文、真实客户数据写入日志或文档。
- 受众模式解析后仍必须经过 `GeekBroadcastSafety`、target 去重和附件 transport 边界。
- 本轮不运行本机 Geek CI，不启动本机 runner，不影响其他仓库 CI；自动验证仅使用 GitHub 托管 CI。

## 确定性验收

| 验收 ID | 对应需求 | 判定条件 |
|---|---|---|
| `AT-UI-001` | `BR-UI-002/003` | all 模式忽略旧选择；exclude 模式以完整聊天为基础并移除排除项。 |
| `AT-SAVE-001` | `BR-SAVE-002/003` | 持久化 reject/false 时内存/UI 不提交；同一按钮的并发操作被阻止。 |
| `AT-SAVE-002` | `BR-SAVE-004` | 畸形记录被安全过滤，消息与群组集合输出稳定且不修改输入。 |
| `AT-TAG-001` | `BR-TAG-001/002` | 同名覆盖保留集合 ID；清除筛选后当前 selected IDs 不变。 |
| `AT-FEEDBACK-001` | `BR-FEEDBACK-001` | Job controller 不包含 `window.alert =` 或 alert filter。 |
| `AT-FAIL-001` | `BR-FAIL-001` | Job failed records 生成带 BOM 的 CSV，并正确转义逗号、引号和换行。 |

## 回滚与真实门禁

- 回滚单位为本契约对应提交；附件交付模块和账号级 Job Manager 不回滚。
- GitHub CI 通过只证明数据模型、contract 和静态集成；真实客户端仍需核验保存/覆盖/删除、账号切换、各受众模式和失败导出。
