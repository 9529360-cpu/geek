# 群发最终实现约束（2026-08-24）

> 本文件是 Issue #165 / #167 当前实现的最终约束。若早期群发文档与本文冲突，以本文和当前代码/contract 为准。特别是早期“全局只允许一个活动任务”“多账号并发放到第二阶段”的描述已经失效。

## 1. 并发与归属

- 不同账号的 Broadcast Job 可以同时执行。例如 A/B/C 各自运行群发时互不占用彼此执行槽。
- 同一账号同一时刻最多一个 executing Job；同账号可以同时保留多个 scheduled / queued Job。
- 同一 Job 内 targets 始终串行发送，并按该 Job 的随机间隔等待，不并行轰炸收件人。
- Job 创建后固定 `accountId / partition / platform / WebView identity / targets / message / attachments / vcards / tagAll / interval` 等业务快照；之后切换账号不得改变发送归属。
- `sendHistory` 显式写回 `job.accountId` 的账号沙箱。

## 2. 账号页任务条

- 任务条只显示当前账号自己的 Job：A 的任务条不会跟随用户切换到 B。
- 切走 A 时 A 继续执行；切回 A 恢复显示 A 的实时状态。
- 当前账号已有 executing Job 时，再点击“群发”只聚焦/显示该账号任务条，不重新打开会清空 targets、附件或运行状态的旧编辑流程。
- scheduled / queued Job 可取消；Job 到 terminal 状态后清理对应 timer 注册。
- completed / stopped / failed 保留为该账号的终态结果，直到用户关闭。
- 即使 Job 在第一个 target 之前失败、`fail === 0`，也必须显示主错误原因并可查看失败详情。

## 3. 定时任务

- 定时任务使用创建时固定的 `accountId` 和 fixed-target snapshot；触发时绝不读取当时正在查看的账号作为发送 owner。
- 同账号定时任务到点时若已有 executing Job，转为 queued；上一任务 terminal 后只 drain 同账号队列。
- 重启恢复的 due Job 若账号 WebView 暂未就绪可以重试；最多 20 次。耗尽后转为 failed，错误码 `BROADCAST_SCHEDULE_ACCOUNT_UNAVAILABLE`，不能永久停留在 queued。
- scheduler registry 按 accountId/taskId 隔离；重挂或取消 A 不得清理 B 的 timer。

## 4. 旧 scheduler 迁移

- 旧 `scheduleTasks` 必须先备份，再写入新 scheduled Job / needs-review 记录，最后才清旧 key。
- 历史“当前勾选”任务没有持久化 recipients，不允许猜测，必须要求用户重新确认。
- 旧群组集合只持久化 chatId，没有可靠联系人/群组名称。
- 因此旧任务只要消息使用 `%nc` 或 `%nr`，不得把 chatId 冒充姓名，也不得静默空替换；必须进入 needs-review。
- 不使用姓名变量且拥有明确 saved-group chatIds 的旧任务可迁为 fixed IDs，target `name` 保持空值而不是 chatId。

## 5. 附件生命周期

即时群发与定时群发使用不同生命周期：

- 即时附件继续使用现有 renderer opaque short token；renderer 中历史兼容字段 `filePath` 的值仍只是 token，不是真实路径。
- 定时附件创建时由主进程把 short token 转成 durable opaque ref。
- durable ref 绑定 `accountId + job/taskId`；跨账号或跨 Job 使用必须 fail closed。
- 真实 canonical path 只允许存在主进程 Store，不写入 renderer，也不写入 `accountData`。
- 到点执行前，主进程重新 realpath/stat 校验文件；删除、替换、size/mtime 变化均失败，不发送不确定内容。
- 校验成功后 ref materialize 为绑定当前 main renderer owner 的新 short token，再进入原 WA/TG/LINE attachment transport。
- materialized short token 只存在执行期内存，不回写 immutable Job。
- completed / stopped / failed / 取消 scheduled/queued Job 后清理对应 durable refs。
- 附件限制保持：最多 10 个、单文件 512 MiB、总计 1 GiB。

## 6. 安全边界

以下边界不得因为群发改造而降低：

- `GeekBroadcastSafety.authorizeSend` 的目标聊天和 composer 校验。
- WebView sandbox / contextIsolation / webSecurity 等现有策略。
- renderer 不获得真实附件路径；主进程 owner 校验保持有效。
- WA / Telegram / LINE 原 transport 语义不另起旁路。
- 不为本次维护修改 `package.json.version` 或 release marker。

## 7. 回归前代码完成条件

进入真实客户端回归前，代码/contract 层必须覆盖：

- A/B 多账号 executing Job 可并发，同账号 executing Job 互斥。
- scheduled/queued 同账号排序、碰撞排队、terminal drain。
- 任务条账号可见性、暂停/停止显式 jobId、运行中重复打开保护。
- WebView 恢复重试耗尽转 failed。
- 旧任务 recipient/name 语义 fail closed。
- 定时附件 durable ref 的 owner binding、重启恢复、mutation detection、materialize、terminal cleanup。

代码层满足上述条件后，剩余验收只包括真实 Electron 客户端的 WA/TG/LINE 行为回归，以及标准 CI 能否实际执行并通过全部 `npm test`。
