# 极客翻译网关接口契约

本文件描述 Electron 主进程与极客翻译 Worker 的长期协议边界。具体 provider、model、部署 URL、当前配额和生产状态以 live runtime / Worker / contract / Actions 为准，不在这里固化成实时清单。

## 调用边界

Renderer 与 WA/TG/LINE/Website WebView 只通过受信 IPC 请求翻译，不持有远程翻译服务 URL、服务端密钥或长期订阅凭据。Electron 主进程负责账号沙箱、短期翻译授权、网关选择、超时、故障切换、结果安全校验与本机缓存。

- 正式远程 endpoint 必须使用 HTTPS；仅受控本机开发路径可使用 `127.0.0.1` HTTP。
- 主进程只向翻译 Worker 发送翻译所需文本、语种和线路语义，不发送 `accountId`、Partition、`chatId` 或 WebView identity。
- provider API Key 只存在服务端环境/Secret，不进入 renderer、WebView、桌面缓存或请求 payload。
- 订阅长期会话只与订阅服务交互；翻译 Worker 使用短期 `aud=geek-translate` / `purpose=translate` Bearer JWT。

## `POST /v1/translate`

### Headers

```http
POST /v1/translate
Content-Type: application/json
Authorization: Bearer <short-lived-translation-jwt>
X-Geek-Client: 1
X-Request-ID: <stable-logical-operation-uuid>
X-Geek-Deadline-Ms: <remaining-budget-ms>
```

约束：

- `X-Request-ID` 是一个逻辑翻译操作的稳定 identity。未知传输结果、主/备 endpoint 故障切换和结果协调重试必须复用同一个 ID；不得因为 timeout/connection reset 盲目生成新 ID。
- `X-Geek-Deadline-Ms` 是当前逻辑操作剩余预算，Worker 仍会按服务端最大预算封顶；桌面与 Worker 必须共享同一绝对截止语义，不能让每次 failover 重新获得一整轮超时。
- 调用方取消通过 `Request.signal` 传播；取消或超时只能说明调用方结果未知，不能证明服务端一定没有提交终态。

### JSON Request

```json
{
  "text": "要翻译的文本",
  "source": "auto",
  "target": "it",
  "provider": "auto",
  "route": "primary",
  "operationRoute": "default"
}
```

字段语义：

- `text` / `source` / `target`：翻译业务语义。
- `provider`：产品级 provider 选择语义；客户端不能指定服务端密钥或任意模型名。
- `operationRoute`：稳定业务线路语义，是 request hash 的一部分；同一个 `X-Request-ID` 重试时必须保持不变。
- `route`：当前物理 endpoint/failover 路由，可在同一逻辑操作的主/备切换中变化，因此不参与稳定业务语义 hash。

### `200` 成功

普通完成示例：

```json
{
  "text": "Traduzione",
  "source": "zh",
  "target": "it",
  "engine": "provider-id",
  "route": "primary"
}
```

如果同一 request ID 的终态已经提交、但原响应丢失，后续同语义请求返回同一可用结果并附带：

```json
{
  "text": "Traduzione",
  "source": "zh",
  "target": "it",
  "engine": "provider-id",
  "route": "primary",
  "replayed": true
}
```

`replayed: true` 不代表再次执行翻译；它必须来自已提交终态的加密结果回放，不得再次调用 provider、再次扣费或再次退款。

## 幂等与 outcome reconciliation

服务端以 `translation_usage.request_id` 为唯一幂等 identity，并在支持迁移 006 的 schema 上用用途隔离 keyed hash 绑定：用户、request ID、原文、源/目标语言、provider、稳定 `operationRoute` 与协议版本。

同一个 request ID 的状态语义：

- `not_started`：没有对应用量行；通过新操作 admission 后才允许建立 reservation。
- `reserved/in_progress`：已有 owner 正在处理，返回 `409 {"error":"request_in_progress"}`。桌面必须在原 deadline 内有界退避协调，不能把它当成终态 conflict，也不能因此标记 endpoint unhealthy。
- `complete` 且语义一致、回放仍有效：返回 `200` + `replayed: true`。
- 相同 ID 但语义不一致：返回 `409 {"error":"request_conflict"}`，fail closed。
- 已完成但 24 小时加密回放窗口已过：结果不再恢复；不得重新执行同一已计费终态。

协调轮询和完成回放不是“新逻辑翻译操作”，不再次占用新操作 admission 配额。真正新操作仍执行用户/IP admission 限流、额度预留和 provider 调用。

## 计费与隐私边界

- 额度、字符计数、reservation、完成/退款状态以服务端 D1 为权威；桌面不得在服务端结算后再次上报扣费。
- 新操作在 provider 调用前预留原文字符；provider/请求在终态提交前失败或取消时，仅 reservation owner 可以退款并删除占位。
- 成功终态把译文字符扣减、`complete` 状态和加密 replay metadata 放在同一 D1 terminal batch 中，保证结果恢复与价值结算同一提交边界。
- D1 不保存聊天原文明文或译文明文。短期结果回放使用 AES-GCM 密文；AAD 绑定 request ID、user ID 与 request hash。
- 加密回放窗口为 24 小时，过期密文在访问和维护路径中有界清理。
- request hash、replay 密文、Authorization、JWT、聊天正文和用户数据不得进入公开健康响应、Issue、PR 评论或常规日志。

## 主要错误语义

错误体以 `error` code 为稳定机器语义；HTTP status 用于大类。当前关键状态包括：

- `400`：输入/请求 identity/route/provider 不合法；
- `401`：`unauthorized`；
- `402`：`quota_exhausted`；
- `409`：`request_in_progress`、`request_conflict`、终态 duplicate/expired 类状态；
- `413`：payload 过大；
- `429`：新逻辑操作 `rate_limited`；
- `499`：`request_aborted`；
- `502`：provider/结果恢复失败类错误；
- `503`：服务配置不可用；
- `504`：`deadline_exceeded`。

桌面端必须区分 `request_in_progress` 与终态 conflict；网络错误/5xx/504 是否允许切 endpoint 由 Translation Runtime 分类器决定，但任何重试都必须保留同一个逻辑 request ID 和稳定业务语义。

## 公开 `GET /health`

健康检查只暴露非敏感服务/provider 状态与允许的聚合诊断信息。不得返回上游原始 `lastError`、请求正文、request ID、request hash、replay 密文、JWT 或用户级数据。

## 账号沙箱翻译缓存

服务端 outcome replay 与桌面本机翻译缓存是两个不同层次：前者解决“服务端已提交但响应丢失”的 value/result 一致性，后者减少普通重复翻译网络调用。

- 每个极客账号独立缓存，文件位于该账号 Electron `Partitions/<partition>/` 范围内；
- 缓存键由原文和稳定翻译配置计算，不把原文明文作为持久化 key/value 写入缓存文件；
- 译文使用 Electron `safeStorage` 加密后持久化；安全存储不可用时只使用本进程内存，不降级为明文落盘；
- 普通自动翻译命中有效缓存时不调用远程翻译服务；
- `refresh: true` 绕过本机缓存，但远程请求仍必须遵守 request identity、服务端计费与 outcome recovery 契约；
- 删除账号时清理该 partition 的内存、在途请求、缓存写入与持久化沙箱，不把旧账号结果继承给重新添加的账号。
