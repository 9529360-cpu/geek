# 极客翻译网关接口契约

## 调用边界

渲染层和 WhatsApp WebView 只提交文本、语种与聊天上下文，不持有、显示或传递服务 URL。Electron 主进程根据部署配置选择极客翻译服务：

- 开发环境未配置时使用本机测试服务；
- 正式打包版必须通过 `GEEK_TRANSLATION_GATEWAY_URL` 配置 HTTPS 远程服务；
- 未配置远程服务时正式版拒绝翻译，不回退或暴露本机地址；
- DeepL、Google、Azure、OpenAI 等供应商密钥始终只在服务端。

### 服务端 Endpoint（仅主进程可见）

```http
POST /v1/translate
Content-Type: application/json
X-Geek-Client: 1
X-Geek-Translation-Intent: outgoing-send | message-display
```

`X-Geek-Translation-Intent` 是 QoS 元数据，不是授权凭据：

- `outgoing-send`：用户正在发送消息前触发的翻译；
- `message-display`：收到消息、历史消息、自动显示等后台翻译；
- 缺失、未知或非法值一律按 `message-display` 处理，不能因为字段缺失获得高优先级；
- intent 不进入翻译正文、不进入缓存键，也不能替代 JWT、额度、质量校验或账号授权；
- 主进程通过请求级异步上下文写入该 Header，禁止依赖目标语言、DOM、焦点或缺失字段推断优先级。

### Request

```json
{
  "text": "要翻译的文本",
  "source": "auto",
  "target": "it",
  "provider": "local",
  "route": "default"
}
```

### Response 200

```json
{
  "text": "翻译后的文本",
  "source": "zh",
  "target": "it"
}
```

### Error

```json
{
  "error": "错误说明",
  "code": "quota_exceeded"
}
```

## 服务端职责

- 身份认证和租户隔离；
- 套餐、额度和字符数统计；
- provider 路由；
- 供应商 API Key 只放服务端密钥存储；
- DeepL/Google/Azure/兼容大模型适配；
- 超时、重试和限流；
- 默认不记录原文、译文和聊天内容；
- 错误日志脱敏；
- 只记录必要的用量和审计信息。

## 限流与交互流量保留

生产网关继续保持原有总上限，不通过提高总额度掩盖调度问题：

- 每用户总上限：`30 / 60s`；
- 每 IP 总上限：`60 / 60s`；
- `message-display` 每用户后台子预算：`20 / 60s`；
- `message-display` 每 IP 后台子预算：`40 / 60s`。

后台子预算位于总上限内部，因此在同一用户或共享 NAT/IP 被后台自动翻译占满时，仍名义保留至少 `10` 个用户级和 `20` 个 IP 级请求位给 `outgoing-send`。后台子预算先判定；被后台预算拒绝的请求不得继续消耗总预算。`outgoing-send` 仍受原有总上限、JWT、额度和上游安全边界约束，不获得无限制通道。

桌面端同时执行本地有界调度：总并发保持 `20`，后台最多占用 `16` 个活跃槽，保留 `4` 个槽给发送前翻译；队列按账号轮转，同账号保持 FIFO，后台积压有界并优先丢弃陈旧后台任务，而不是让发送前翻译排在无限后台队列之后。

## Provider 规划

```text
standard   → DeepL/Google/Azure 等标准翻译 API
premium    → 高质量大模型
custom     → 客户自有服务端配置（不把 Key 下发客户端）
```

客户端不感知 provider，只依赖统一 `/v1/translate` 合同。

## 安全约束

- 正式版主进程只允许 HTTPS；仅未打包开发环境可使用 `127.0.0.1`；
- 服务 URL 不进入 renderer、WebView、localStorage 或翻译请求 payload；
- 客户端的 `provider`/`route` 只是产品线路偏好，服务端决定真实供应商与模型，客户端不能传入供应商密钥或模型名；
- `accountId` 只在 renderer → Electron 主进程边界使用，用于选择本机账号沙箱；不发送给翻译服务；
- 主进程只把文本、语种、产品线路和上述无身份含义的 QoS intent Header 发送给翻译服务，不发送 `chatId`、`accountId` 或 Partition；
- 生产服务应使用短期会话认证，而不是长期 API Key 写入客户端；
- intent 只影响排队和限流类别，绝不改变鉴权、扣费、输出质量校验或“翻译失败不得发送原文”的 fail-closed 规则。

## 账号沙箱翻译缓存

- 每个极客账号独立缓存，文件位于该账号的 Electron `Partitions/<partition>/` 目录；
- 缓存键为原文和翻译配置的 SHA-256，不把原文明文写入缓存文件；
- 译文使用 Electron `safeStorage`（Windows DPAPI）加密后追加保存；安全存储不可用时只使用本次进程内存，不降级为明文落盘；
- 缓存不自动过期、不按条数淘汰，生命周期与账号沙箱一致；
- 普通自动翻译命中缓存时不调用远程翻译服务；
- 右键“重新翻译”使用 `refresh: true` 绕过缓存，并以刷新结果覆盖同键的旧结果；
- 删除账号时清理内存、在途请求和写入队列，并物理删除整个 Partition；重新添加同一号码会获得新沙箱，不继承旧缓存。
