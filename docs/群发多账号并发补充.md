# 群发多账号并发补充

> 本文覆盖 `docs/群发体验与账号级任务改造.md` 中“第一版只允许一个活动 Broadcast Job / 多账号并发放第二阶段”的旧限制。该限制自本文起废止。

## 结论

极客本身采用多账号 WebView 常驻模型，不同账号之间具备天然并发基础。群发不能继续以窗口级单任务设计为目标。

本轮账号级 Job 重构完成后，应直接支持：

- 账号 A 正在群发时，账号 B 可以创建并运行自己的群发；
- A/B/C/D/E 等不同账号可以同时存在活动任务；
- 每个账号同一时间最多一个活动群发 Job；
- 同一个账号内部仍按既有顺序逐个 target 发送，不把单账号 target 改成并行轰炸。

## 正确数据模型

运行态：

`broadcastJobs = Map<accountId, BroadcastJob>`

每个 `BroadcastJob` 独立保存：

- `id`
- `accountId`
- `partition`
- `webview / guestId`
- `targets`
- `message`
- `files`
- `vcards / tagall / send options`
- `intervalMin / intervalMax`
- `state`
- `current / total / ok / fail`
- `failed[] / failReasons[]`
- `paused / stopRequested`
- `createdAt / finishedAt`

任务运行过程中不得再从 `activeId`、当前编辑弹窗或其他账号 UI 状态读取任务归属或发送参数。

## UI 规则

右上角任务条仍然是账号页内任务条，不是全局任务条。

- A 页面：只显示 A 的任务条；
- 切到 B：只显示 B 的任务条（如果 B 有任务）；
- B 没任务：不显示 A 的任务条；
- A/B 同时发送时，切换账号只是切换看到哪一个任务状态，不改变任何后台任务；
- 同账号已经有活动 Job 时再次点群发：显示/聚焦该账号任务状态，不再创建第二个同账号 Job。

## 暂停与停止

暂停/停止必须作用于明确的 `accountId` / `jobId`。

禁止继续使用窗口级：

- `broadcastPaused`
- `broadcastStop`
- `broadcastRunning`

否则暂停 A 会误伤 B。

目标接口应类似：

- `pauseBroadcastJob(accountId)`
- `resumeBroadcastJob(accountId)`
- `stopBroadcastJob(accountId)`

## 发送历史与失败结果

每个 Job 独立完成后：

- `sendHistory` 写回 `job.accountId`；
- 失败名单属于 `job.accountId`；
- 失败导出读取该账号对应 Job；
- 任务完成后切到其他账号不能改变 owner。

## 定时任务

当前全局 `scheduleTaskTimers` 需要改成账号级 registry：

`scheduleTaskTimersByAccount = Map<accountId, Map<taskId, timer>>`

规则：

- A 账号重新加载/重挂定时任务，只操作 A 的 timers；
- 切到 B 不得 `clearTimeout` A 的 timers；
- 每条 schedule task 持久化明确 `accountId`；
- 到点时创建对应账号的 Broadcast Job；
- 如果该账号已有活动 Job，定时任务不得静默串入现有任务；需要明确排队/标失败/延后策略，第一版优先 fail-closed 并记录“账号当前已有群发任务”，不要误发；
- 不同账号的定时任务可以同时触发并运行。

## 并发边界

允许：

- A 与 B 同时群发；
- WhatsApp A + Telegram B + LINE C 同时运行；
- 不同账号各自拥有独立间隔和进度。

不在本轮做：

- 同一账号同时跑两个群发 Job；
- 同一 Job 内多个 target 并行发送；
- 为追求吞吐改变既有安全校验或风控间隔。

## 新验收

1. A 群发运行时切到 B，B 可以正常创建自己的群发；
2. A/B 两个 Job 同时运行，暂停 A 不影响 B；
3. 停止 B 不影响 A；
4. 切到 A 只看到 A 任务条，切到 B 只看到 B 任务条；
5. A/B 的 `sendHistory`、失败名单、完成状态分别写入自己的账号沙箱；
6. A/B 定时任务同时存在时，切账号不会清掉对方 timer；
7. A/B 定时任务可在接近时间点分别触发自己的账号 Job；
8. 所有 WA/TG/LINE transport 与 `GeekBroadcastSafety` 行为保持原语义。
