# 账号沙箱数据边界

更新时间：2026-08-19

## 目标

每个账号都使用独立 partition，并把桌面工具数据持久化到该 partition 对应的 Electron `userData` 目录。账号切换时只能读取当前账号自己的数据；删除账号时必须先排空写入，再由现有账号删除流程清除整个 partition。

当前文件：

```text
<userData>/Partitions/<partition>/geek-account-data.jsonl
```

该文件保存的是应用工具状态，不保存 WebView 的 Cookie、登录凭据、聊天正文抓取结果或 LINE auth header。

## 当前持久化边界

Electron 启动入口先安装 `src/account-data-boundary.cjs`，再加载 `src/main.cjs`。因此 `main.cjs` 中保留的旧 `account-data:*` 处理器不会成为活动处理器；实际读写由 `src/account-data-store.cjs` 负责。

主 renderer 只通过以下 IPC 操作账号数据：

- `account-data:get-all`
- `account-data:set`
- `account-data:remove`

边界会验证请求来自当前桌面主窗口，并从 `userData/accounts.json` 重新确认账号存在及其固定 partition。renderer 不能提交 partition 或文件路径。

## 允许写入的 key

主进程采用显式 allowlist，并由 contract 与 `ui/app.js` 的 `ACCOUNT_SANDBOX_KEYS` 保持完全一致：

- `__schema`
- `scheduleTasks`
- `sendHistory`
- `savedMessages`
- `savedLists`
- `broadcastExclude`
- `broadcastExcludeContacts`
- `broadcastExcludeGroups`
- `broadcastGroups`
- `savedGroups`
- `groupLinks`
- `gtAutoCfg`
- `gtCmdCfg`
- `gtCmdNames`
- `translationGlobal`
- `translationChats`

新增 key 必须同时更新 renderer 常量、主进程 allowlist 和聚焦 contract。只满足字母数字格式但未列入 allowlist 的 key 会被拒绝。

## 加密与单条限制

- 每条 value 在写盘前使用 Electron `safeStorage` 加密，JSONL 只保存 Base64 密文。
- `safeStorage` 不可用时读写均 fail closed，不降级保存明文。
- 单个 value 最大 2 MiB。
- 单条物理 JSONL 记录最大 3 MiB，防止损坏或恶意超长行造成无界内存增长。
- 日志和错误信息不得包含 value、聊天正文、token、Cookie 或真实运行数据。

## 写入顺序与一致性

每个 partition 使用独立串行队列。一次 set/remove 的顺序为：

1. 校验 sender、账号、partition、key 和大小；
2. 确认安全存储可用并生成加密记录；
3. 以 append 模式打开 JSONL；
4. 写入完整记录并 `fsync`；
5. 关闭句柄；
6. 只有前述步骤成功后才更新内存 cache；
7. 达到阈值时尝试 compaction。

append 失败时，IPC 返回失败，内存 cache 保持写入前状态，避免“界面已变但重启丢失”。

## 加载与损坏恢复

日志通过流式读取恢复，不使用无上限 `readFile`。

- 完整记录按顺序回放；同一 key 的最后一条有效记录获胜。
- `deleted: true` 删除对应 key。
- 未知 key 会被忽略，并在下一次 compaction 中清除。
- 仅最后一个未完整写完的尾行可作为中断 append 被忽略；随后立即尝试 compaction 修复。若原子替换暂时失败，读取仍可返回最后完整状态，但新的 set/remove 会被拒绝，避免把新记录拼接到损坏尾行之后。
- 已以换行结束的损坏记录或任何日志中段损坏会显式失败，不静默跳过。
- 解密失败按记录损坏处理，不返回伪造的空数据。

## Compaction 与原子替换

满足任一条件时触发 compaction：

- 日志记录数达到 512；
- 文件大小达到 64 MiB；
- 发现损坏尾行或旧的未知 key。

Compaction 只保留每个允许 key 的当前值：

1. 在同一目录写入 `geek-account-data.jsonl.compact.tmp`；
2. 写入加密快照并 `fsync`；
3. 关闭临时文件；
4. 使用同文件系统 `rename` 原子替换正式文件；
5. 在支持的平台尽力同步目录。

若 rename 失败，原 append 日志保持不变，本次已成功 append 的写入仍视为成功；临时文件尽力清理，下一次写入会重试 compaction。

启动恢复规则：

- 正式文件存在时，正式文件为权威来源，遗留 temp 被删除；
- 正式文件缺失且 temp 是完整、可解密、仅含允许 key 的快照时，temp 被提升为正式文件；
- 无效 temp 不会被当成空数据覆盖或静默提升。

## 删除账号

`accounts:remove` 由账号数据边界包装：

1. 标记 partition 正在删除，拒绝新的账号数据操作；
2. 等待该 partition 已排队或正在执行的 append 完成；
3. 调用现有账号删除处理器；
4. 账号删除成功或账号状态已移除时，丢弃内存 cache；
5. 若删除在账号状态仍存在时失败，解除删除标记，允许继续使用。

这可以避免晚到的 append 在 partition 目录被删除后重新创建 `geek-account-data.jsonl`。

## 验证

相关 contract 覆盖：

- allowlist 与 renderer key 对齐；
- 密文落盘和安全存储 fail closed；
- 重复 key、删除记录与阈值 compaction；
- 损坏尾行修复和中段损坏拒绝；
- append 失败时内存/磁盘一致；
- rename 失败后保留原日志并重试；
- 孤儿 temp 恢复；
- 删除账号前排空写队列；
- 旧 `main.cjs` account-data IPC 处理器保持失活。
