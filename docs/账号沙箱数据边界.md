# 极客账号沙箱数据边界

## 核心原则

一个极客应用账号对应一个独立 Electron Partition。该 WhatsApp、Telegram 或 LINE 账号从创建后产生的账号级数据，生命周期全部跟随该 Partition。

## 必须进入账号沙箱的数据

- Cookie、登录态、localStorage、IndexedDB、Cache、Service Worker；
- 翻译全局设置、当前聊天设置、加密译文缓存；
- 群发保存消息、联系人/群组集合、排除名单；
- 定时任务、发送历史；
- 群组链接、群组工具设置、指令配置；
- 任何包含聊天 ID、群组 ID、联系人 ID、号码或账号行为的本地数据。

账号业务数据通过主进程 `account-data:*` IPC 写入：

```text
Partitions/<partition>/geek-account-data.jsonl
```

值由 Electron `safeStorage`（Windows DPAPI）加密，文件只暴露通用键名、时间和密文。安全存储不可用时必须明确失败，不得降级明文或静默假保存。

## 可以保持产品全局的数据

仅限与任何号码无关、删除账号后仍应保留的产品设置，例如：

- 软件主题、强调色；
- 窗口尺寸和位置；
- 产品更新设置；
- 平台定义和通用功能开关。

若数据包含账号、聊天、联系人、群组或发送行为，就不能归入产品全局。

## 切换账号

1. 加载目标账号 Partition 的加密业务数据；
2. 使用切换序号丢弃较早的异步切换结果；
3. 加载完成后才更新 `activeId`；
4. 取消上一个账号的前台定时器，清空勾选和筛选；
5. 重绘保存消息、列表、群组、排除项和翻译配置；
6. 给各常驻 WebView 注入配置时显式使用该 WebView 对应的 `account.id`，禁止依赖当前前台账号。

## 删除账号

```text
标记 Partition 已删除
→ 清账号业务内存、翻译缓存、在途请求和写队列
→ 销毁该账号 WebContents
→ 清 Electron Session/Cookie/Cache/Auth
→ 物理删除 Partitions/<partition>
→ Windows 文件锁失败时有限重试并在退出时兜底
```

删除后，迟到的翻译结果和排队写入不得重建目录。重新添加同一号码会获得新的 accountId 和 Partition，不继承旧数据。

## 验收要求

- A/B 两个真实账号写不同值，切换和重启后仍各自读取；
- A 的群发保存消息、群组列表和翻译配置在 B 中不可见；
- 快速点击 A→B 或 B→A，最终主进程 activeAccountId 与 UI 一致；
- 创建临时账号并写入探针后删除，IPC 应报告沙箱不存在，Partition 搜索结果为 0；
- 磁盘文件不得出现消息、号码、群名、链接或译文明文。
