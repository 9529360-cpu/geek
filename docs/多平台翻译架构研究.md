# 多平台翻译架构研究

## 结论

翻译和群发在业务职责上独立，但底层平台能力应共用：当前聊天、聊天列表、消息观察、消息解析、输入框、发送文本和发送媒体。

推荐结构：

```text
公共翻译核心
  配置 / 收发语言 / 缓存 / 请求队列 / 译文显示 / 重试 / 竞态
公共群发引擎
  任务 / 随机间隔 / 排除 / 记录 / 暂停恢复
共享平台适配器
  getCurrentChat / listChats / observeMessages / parseMessage
  getComposer / setComposerText / sendText / sendMedia
    ├─ WhatsApp
    ├─ Telegram
    ├─ LINE
    └─ LINE Business
```

## HaloGPT证据

解包目录：`D:\项目\agent\halogpt_extract\app_extracted`

公共翻译核心：`dist-electron/main/se8le.js`

证据：

- `translateApi`、`getTranslateCache`、`saveTranslateCache`；
- `pushTranslateQuery`、`sendTranslateQuery`；
- 请求并发上限 `limitCount=20`；
- 当前应用等待队列；
- `sendFrom`、`sendTo`、`msgFrom`、`msgTo`、`isGroup`；
- `attachTranslateMessage`；
- `prohibitSendZh`、`openSend`、`openMsg`；
- 发送和收到消息使用同一个翻译核心。

平台适配器：

|---|---|---|
| Telegram Web A | `dist-electron/main/sidk4T.js` | `#Main`、MutationObserver、消息节点和发送输入链路 |
| LINE | `dist-electron/main/mw1fq.js` | LINE消息解析、译文挂载、X-Line-Access/X-Line-Application内部请求 |

三个适配器都调用同一个 `attachTranslateMessage`，并传入 `msgBox/text/isSelf/from/to/getText/isOld/pause`。

## HelloWorld证据

解包目录：`D:\项目\agent\hw_extract\resources\app.asar.unpacked\store`

| 平台 | 文件 | 观察到的结构 |
|---|---|---|
| Telegram | `store/telegram/index.js` | 收发拦截、sendLock、输入框回填、翻译后再触发发送、可见消息翻译 |
| LINE | `store/line/index.js` | 翻译请求、输入框回填、消息译文节点和发送锁 |
| LINE Business | `store/linebusiness/index.js` | React输入值变更、发送按钮触发、消息节点解析和翻译缓存 |

HelloWorld平台文件重复较多，但它提供了重要的真实平台细节：选择器、React输入更新、发送按钮/Enter事件、消息方向和媒体处理。

## 极客移植原则

1. 不复制HelloWorld三份公共状态机；只移植平台细节。
2. 采用HaloGPT公共翻译核心的职责拆分。
3. WhatsApp已验逻辑先保持不变，先建立适配器边界。
4. TG/LINE适配器只能通过统一消息模型和翻译请求接口工作。
5. 群发和翻译共享平台适配器，但共享的是能力，不共享业务数据。
6. 任何平台真实发送回归前，先使用草稿/输入回填验证，避免误发。
